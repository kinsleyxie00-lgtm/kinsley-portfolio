# Projects 视频展示与 About 标题更新设计规格

## 目标与边界

本轮在现有 Precision Editorial 视觉方向内调整 About 与 Projects，不重新设计 Hero、Experience、Photography、Contact 或导航。

所有经历、数据、职责、账号链接和视频内容仍以用户后续提供的真实资料为唯一事实源。没有资料的部分只建立可替换的结构，不在正式页面中虚构名称、数据或成果。

## 1. About 手写标题

- 保留现有 `01 / PROFILE`、人像、中文介绍与简历下载入口。
- 使用用户提供的手写 `about me` 图片替换当前衬线中文标题“关于我”。
- 手写标题使用透明背景素材，完整显示、不裁切、不拉伸。
- 桌面端与移动端都保持克制尺寸，使其成为标题而不是装饰海报。

## 2. Projects 顺序

Projects 调整为以下顺序：

1. 小红书个人账号：首项、重点案例，拥有最大的页面篇幅与视觉权重。
2. Moving Image：单支 4:3 MV 成片展示，替换当前含保密内容的节点 Campaign。
3. firefly Big Day：保留可公开内容，作为更紧凑的项目索引。

不得继续展示得物内部运营、节日企划、会场、数据复盘或其他保密内容。

## 3. 小红书个人账号重点模块

### 信息结构

- 小标签：`01 — XIAOHONGSHU / PERSONAL ACCOUNT`。
- 主标题沿用已确认的编辑语气，暂以结构文案呈现；最终账号介绍、指标与主页链接等待用户提供。
- 展示三个真实指标的位置，但仅在获得真实数据后写入页面。
- 提供清晰的账号主页外链入口；链接在获得真实 URL 后启用。
- 不设置“亮点笔记”独立板块，因为三个重点内容本身均为视频笔记。

### 三个视频笔记

- 一共展示三个视频。
- 每个视频画面严格使用 `3 / 4` 纵向比例。
- 视频画面下方设置独立文案框；文案框不属于 `3 / 4` 画幅。
- 文案框包含真实标题与真实互动数据的位置，待素材补齐后写入。
- 默认三个卡片等大并列。
- Hover 或键盘聚焦某一卡片时，该卡片整体等比放大，另外两张等比缩小。
- 放大过程中视频画面始终保持 `3 / 4`，文案框不变形，三张卡片底部对齐。
- Hover 仅改变视觉主次，不自动播放；点击后在卡片原位置播放。
- 同一时间只播放一个视频；开始播放新视频时暂停其他视频。
- 默认静音由浏览器控件决定，不自动播放、不突然发声。

### 移动端

- 移动端不模拟 Hover 放大。
- 三个 `3 / 4 + 文案框` 卡片采用横向滑动：当前卡片完整显示，并露出下一张的一部分作为继续浏览提示。
- 横向滑动使用滚动吸附；页面本身不得产生横向溢出，文案框必须完整可读。
- 点击播放、暂停与账号主页链接均须保持至少 44px 的可操作区域。

## 4. Moving Image 模块

### 内容与语言

- 小标签：`02 — MOVING IMAGE`。
- 标题：`In the Act of Becoming`。
- 副文案：`Light, texture and transformation.`。
- 只以中性独立影像作品呈现，不写歌名、歌手、官方 MV、翻拍、Cover、课程、练习或作业。
- 不展示 brief、内部策划、数据、复盘、故事板或其他保密内容。

### 播放器

- 只展示一支成片。
- 画面严格为 `4 / 3` 横向比例。
- 默认直接显示成片原始胶片调色封面，不添加暗色遮罩、渐变遮罩或额外调色。
- Hover 时播放器不放大、不缩放、不裁切、不改变明度，也不引起页面布局移动。
- Hover 或键盘聚焦时，仅播放按钮线条产生轻微反馈，并显示 `WATCH FILM →`。
- 点击后在原位置播放，不打开弹窗。
- 播放器下方保留克制的进度线视觉；实际播放时使用浏览器可访问的播放控制。
- 页面仅保留 `FORMAT / 4:3`、`FILM / 01` 等中性信息；其他元数据等待真实资料。

### 移动端

- 完整保留 `4 / 3` 比例，不裁切为竖屏。
- 标题、播放器和元数据按单列顺序阅读。
- 播放控件不可被鼠标文字标签或固定导航遮挡。

## 5. firefly Big Day

- 作为第三项保留当前可公开的品牌营销与现场执行信息。
- 视觉篇幅小于个人账号与 Moving Image。
- 不新增未经简历或用户资料确认的数据、职责和结果。

## 6. 素材待补清单

正式实现视频内容前需要用户提供：

- 三个小红书视频文件或可直接嵌入的公开地址。
- 三个视频的封面、标题与需要展示的真实互动数据。
- 小红书账号名称、简介、真实指标与账号主页 URL。
- 一支 Moving Image 成片及其封面；封面可以从视频中截取。
- 如需显示额外元数据，提供真实年份、时长与职责。

如果实现时素材仍未提供，页面使用明确的中性占位，不把本地找到但未经确认的文件带入网站。

## 7. 全站轻微鼠标吸引交互

### 原生鼠标与文字标签

- 桌面端始终保留系统原生鼠标，不再使用图形化自定义光标替代它。
- 移除现有 specimen locator 的十字、圆弧、取景框和点击涟漪。
- 保留 `VIEW`、`OPEN`、`CLOSE`、`SELECT` 文字标签；Hero 植物入口继续显示对应章节提示。
- 标签位于原生鼠标右下方约 16px，不覆盖鼠标热点，也不遮挡正在阅读的文字。
- 标签只使用轻微淡入、位置跟随与淡出，不发光、不缩放、不产生轨迹或额外装饰。
- 标签为纯视觉辅助，使用 `pointer-events: none`，不可抢占按钮或链接事件。

### 吸引规则

- 在 Hero 与所有内页使用同一套轻微吸引逻辑。
- 鼠标附近约 140px 范围内的短标题、导航文字、项目标签、图片与植物可以响应。
- 元素根据鼠标距离向鼠标方向移动 2—6px，并产生最多 0.5—1° 的轻微倾斜。
- 距离越近，位移越接近上限；超出作用范围后立即进入回位阶段。
- 鼠标离开元素后，在 300—500ms 内平滑回到原位置，推荐默认回位时间约 400ms。
- 吸引只使用 `transform: translate3d(...) rotate(...)`，不改变布局尺寸。
- 不使用缩放、发光、阴影增强、拖尾、裁切角标或额外 UI。
- 吸引效果不得改变文字颜色、图片裁切、植物入口的点击区域或视频画幅比例。

### 适用与排除

- 适用对象：Hero 短标题与植物入口、导航文字、内页章节标题、短标签、人物/项目/摄影图片、项目视频封面。
- 不作用于长段正文、Contact 联系信息、原生视频控制条、正在播放的视频内容、明信片/项目弹层内容和表单控件。
- 小红书视频卡片的 Hover 等比放大与吸引效果相互独立：卡片外层负责等比放大，内部封面最多应用轻微位移与倾斜，禁止叠加缩放。
- Moving Image 播放器本体不缩放；只允许其播放标记或短标签使用轻微吸引，确保已确认的 4:3 画面与静态布局不变化。
- 触屏、粗指针设备和 `prefers-reduced-motion: reduce` 环境关闭吸引与跟随标签，恢复普通原生交互。

### 实现边界

- 使用单个全局 `pointermove` 监听器和单个 `requestAnimationFrame` 更新循环，不为每个元素注册独立的连续监听器。
- 通过显式数据属性标记允许吸引的元素，避免自动选择所有标题、图片或正文。
- 页面切换、弹层打开、组件卸载和设备条件变化时，必须清理动画帧、引用与状态，并将元素 transform 复位。
- 全局交互组件只负责计算鼠标距离、文字标签和吸引 transform；各业务组件继续负责点击、播放、页面切换和弹层状态。

## 8. 无障碍、性能与验证

- 视频必须支持键盘聚焦、播放和暂停。
- 所有 Hover 反馈均提供等价的 `:focus-visible` 状态。
- 尊重 `prefers-reduced-motion`；关闭动效时直接切换视觉状态。
- 视频使用 `preload="metadata"` 或更克制策略，避免三个视频在进入页面时同时完整下载。
- 验证桌面端 1440px 与移动端 390px。
- 检查三个小红书视频比例、Hover 等比变化、单一视频播放约束、MV 的 4:3 原位播放、外链与焦点顺序。
- 验证原生鼠标始终可见，标签不遮挡点击，吸引位移与倾斜不超过规格上限。
- 验证 Hero 与各内页使用一致的吸引手感，长正文、Contact、弹层和原生视频控件不受影响。
- 验证快速移动鼠标、频繁切页和打开/关闭弹层后没有残留 transform、动画帧或控制台错误。
- 验证触屏、粗指针和减少动态效果环境不运行吸引逻辑。
- 运行 TypeScript 检查与生产构建，并检查浏览器控制台。

## 不在本轮范围内

- 不部署。
- 不修改其他页面的内容方向。
- 不公开或推测任何保密内容。
- 不根据文件名擅自选择用户尚未确认的视频。
- 不恢复程序化树根或新建首页、导航。
